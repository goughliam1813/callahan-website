Ask, write, run, report.

The same shape as Quartet QE. Crescendo finds what it needs in your team's context, asks only for what is missing, and never sends load itself: Gatling does.

Ask

"How much can the order pipeline take?" in plain words.

Read

Environments, contracts, SLOs, traffic models and principles.

Write

A plain Gatling Java simulation you can review.

Check

Compiled and checked against the principles and the allowlist.

Run

Smoke first, then the profile split across N injectors.

Report

SLO verdict, the knee, and what moved with latency.

Ordinary Gatling.

Drafts are plain Gatling Java. Crescendo adds four calls: named targets instead of URLs, a 1/N share for each injector, arrivals counted with a kill switch, and latency recorded into HDR histograms.

DemoCatalogLoadSimulation.java (excerpt)Drafted from OpenAPI
// No URLs in tests: the allowlist and container routing work
HttpProtocolBuilder protocol = http.baseUrl(Targets.url("demo-catalog"));

ChainBuilder placeOrder = Crescendo.timed(http("place order")
        .post("/orders")
        .check(status().is(200)), "place order");

ScenarioBuilder buyJourney = scenario("buy")
        .exec(Crescendo.start())
        .feed(data)
        .exec(listProducts)
        .pause(Duration.ofMillis(300), Duration.ofMillis(1500))
        .exec(getProduct)
        .pause(Duration.ofMillis(300), Duration.ofMillis(1500))
        .exec(placeOrder);

// buy: 15% of journeys. Each injector takes 1/N of the rate
buyJourney.injectOpen(
    rampUsersPerSec(Shard.rate(0.0)).to(Shard.rate(18.0)).during(Duration.ofSeconds(15)),
    constantUsersPerSec(Shard.rate(18.0)).during(Duration.ofSeconds(45)))

Pick the test by the question.

Seven test types, each with a default open-model profile built from your traffic model's peak rate. Every new simulation starts with a smoke run.

SmokeDoes the script work and is the system up? Its numbers are the no-load baseline.
LoadDo we meet the SLOs at the expected peak? Judged on the steady state, after the warm-up.
StressWhat happens above the peak, and do we degrade gracefully?
SpikeDo we survive a sudden burst and recover? Flash sales, push notifications, retry storms.
SoakDo we stay healthy for hours? Leaks, pool exhaustion, GC drift.
BreakpointAt what rate do we stop meeting SLOs? Expect it to abort: that is the answer.
ScalabilityDoes throughput rise with load, and where is the knee?

APIs, sites and event streams.

Crescendo drafts a simulation from what your team already has, then the AI edits it.

OpenAPIOne scenario per journey at its share of the rate, with think time and unique data.

browse 60%, search 25%, buy 15%

Recorded journeyA browser journey recorded as HAR becomes protocol load, while a few real Chromium browsers capture Web Vitals under that load.

TTFB, FCP, LCP, CLS and load time

KafkaEach arriving user produces one message. Produce latency, end-to-end latency and consumer lag are recorded.

order-events through the order enricher

WebSocket and gRPCDrafts for both; gRPC uses Gatling's gRPC plugin and your stubs.

Same rules, same report

Load from anywhere.

Each injector runs 1/N of the profile and sends its histograms to the coordinator every second, so the combined p99 is the true p99 of every request, never an average of p99s.

One page, verdict first.

The report correlates the run with your metrics, logs and traces, and writes a JUnit file so CI can gate on the SLOs.

SLO verdictJudged by percentiles on the steady state after the warm-up. Never averages.
TimelineLoad, p50, p95, p99, errors and every server metric on one shared time axis.
The kneeThe highest rate where throughput still follows load.
BaselineCompared with the last run a person reviewed and saved.
ObservabilityPrometheus, Loki, Elasticsearch, OpenSearch, Splunk, Datadog, Tempo, Jaeger and Grafana annotations.
Bottleneck analysisThe AI's reading of which series moved with latency, for a person to check.

Guard rails, not guesswork.

Load is a tool you can hurt yourself with. Crescendo is built so the AI cannot.

Allowlisted targetsLoad only goes to hosts you own and listed. Production needs a sign-off file a person wrote.
Kill switchOne command stops every injector. Runs abort on their own when errors or p99 pass your thresholds.
No secrets for the AIYou save them with ./crescendo secret NAME. They are redacted from everything the AI sees.
A person reviewsNothing is pushed or merged. Context and tool output are data, never instructions.
