NATIVE APPS

Not just websites. Your Android app too.

Quartet QE drives native Android apps as well as websites and phone browsers, from the same plain-English story. One story can also check the APIs, queues and databases behind the screen, so a test follows the work all the way through.

HOW IT WORKS

A story in. Proof out.

01 · STORY

Write it in English

Type it, point at a file, or pull a ticket from Jira, Azure DevOps, GitHub or GitLab. No selectors, no scripts.

02 · TESTS

The AI writes the tests

It reads your contracts, telemetry and engineering principles first, reuses the steps you already have, then validates what it wrote.

03 · REPLAY

Record once, replay free

The recording is the test. Reruns, in CI or on your laptop, replay it with no AI at all.

04 · APPROVE

A person decides

An independent review and a traceability matrix go to a review page. You approve; the AI never merges.

THE FIRST RUN

The AI works

  • Reads the story, context and source
  • Writes and validates the tests
  • Records what it did, step by step
EVERY RUN AFTER

The recording works

  • Replays the same steps, no model needed
  • Same result for the same system
  • Screenshots and a step trace in the report
WHAT IT TESTS

The whole stack, in one place.

UI

Websites

Real browser runs with screenshots at every step.

UI

Phone browsers

The same story on mobile browsers, not a resized desktop window.

UI

Native Android apps

Taps, typing and checks inside the app itself.

SERVICE

APIs

Calls checked against your API descriptions, not invented endpoints.

SERVICE

Kafka

Publish and consume, then check what arrived.

DATA

Postgres and MongoDB

Check the data a feature left behind.

WORK

Trackers

Stories from Jira, Azure DevOps, GitHub and GitLab.

CI

Jenkins

Reports publish into your Jenkins build page.

REPORTS

Evidence you can hand to anyone.

Every run produces a branded, self-contained report. Open it in a browser, attach it to a ticket, or publish it from Jenkins.

RESULTS

What passed and why

Each test against the story it came from, in a traceability matrix.

SCREENSHOTS

A picture of every step

Per-step screenshots for each target, so a failure shows you what the user would have seen.

REVIEW

An independent check

A separate review reads the tests before they run and flags what it would not sign off.

SECURITY AND PRIVACY

It runs on your machine, with limits.

Where it runs
On your computer. No account, no server of ours, no usage tracking.
Tools
Every tool is labelled read-only, destructive or open-world, so the app can ask you before anything risky.
Files
File access is confined, symlinks are checked, and credential files are refused.
Secrets
Tokens go in the extension or plugin settings, or a private file. They never go through the chat.
Releases
SHA-256 checksums, a software bill of materials and verifiable build provenance on every release.
